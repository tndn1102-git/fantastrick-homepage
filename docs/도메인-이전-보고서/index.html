어떤 방법으로 옮기나

＊

네임서버를 Cloudflare 로 옮깁니다

새 홈페이지는 Cloudflare 위에서 돌고 있습니다. 여기에 내 도메인을 붙이려면 도메인 관리 자체를 Cloudflare 로 넘겨야 합니다. A 레코드만 바꾸는 걸로는 안 됩니다.

즉 가비아에서 도메인을 뺏어오는 게 아니라, 도메인 소유는 가비아에 그대로 두고 "이 도메인의 주소록을 누가 관리할지"만 Cloudflare 로 바꾸는 것입니다. 도메인 갱신·소유권은 그대로입니다.

그래서 위의 레코드를 전부 Cloudflare 로 옮겨 적어야 합니다. Cloudflare 가 기존 레코드를 자동으로 긁어오긴 하는데 100% 가 아닙니다. 특히 MX·SPF 가 빠지면 메일이 조용히 끊깁니다 — 안 오는 걸 며칠 뒤에 알게 됩니다. 그래서 D단계에서 한 줄씩 눈으로 대조합니다.

준비 — 옮기기 전에

A

지금 걸려 있는 것 전부 적어두기

Claude완료

가비아 DNS 관리 화면도 캡처해 두시면 더 좋습니다. 제가 못 보는 레코드(SRV, 별칭 등)가 있을 수 있습니다.

TTL 을 낮춰둡니다 — 옮기기 하루 전

사장님가비아 DNS 관리

TTL 은 "이 주소를 얼마나 오래 기억해둘지"입니다. 지금 값이 크면 바꿔도 옛 주소를 계속 보는 사람이 오래 남습니다.

전부 300초(5분) 로 내려두면 되돌릴 일이 생겼을 때 빨리 돌아옵니다. 옮긴 뒤 원래대로 올리면 됩니다.

Cloudflare 에 도메인 추가

Claude계정 접근 필요

새 홈페이지가 올라가 있는 그 Cloudflare 계정에 fantastrick.co.kr 을 추가합니다. 추가하면 기존 레코드를 자동으로 긁어옵니다.

D

레코드 한 줄씩 눈으로 대조 — 여기가 제일 중요합니다

Claude빠뜨리면 메일이 죽습니다

자동으로 긁어온 목록을 위 표와 한 줄씩 맞춰봅니다. 특히:

  • MX mailapp.hiworks.co.kr — 없으면 메일 끊김
  • TXT (SPF) — 없으면 보내는 메일이 스팸함으로 감
  • tgc — 없으면 TGC 예약 사이트 접속 불가
  • mail · webmail · hiworks — 없으면 웹메일 접속 불가
  • google-site-verification — 없으면 구글 검색 등록 풀림

이때 tgc·mail 류는 Cloudflare 를 거치지 않고 바로 통과(회색 구름)하도록 둬야 합니다. 메일 관련 이름을 Cloudflare 로 통과시키면 메일이 안 갑니다.

옛 사이트 정리 — 손님이 두 군데 예약하면 안 됩니다

E

옛 사이트에서 예약 접수를 닫습니다

사장님순서를 지켜야 합니다

주소를 바꾸면 몇 시간 동안 어떤 손님은 옛 사이트, 어떤 손님은 새 사이트를 보게 됩니다. 그 사이 옛 사이트로 들어온 예약은 새 사이트가 모릅니다. 같은 시간에 두 팀을 받는 사고가 납니다.

그래서 주소를 바꾸기 전에 옛 사이트 예약 버튼을 막고 "새 홈페이지에서 예약해 주세요" 안내를 띄웁니다.

이 순서를 거꾸로 하면 안 됩니다. 주소부터 바꾸고 옛 사이트를 닫으면, 그 사이에 들어온 예약이 공중에 뜹니다.

필요한 것왜
가비아 도메인 관리 로그인B(TTL)·G(네임서버) 는 여기서만 됩니다. 화면 보면서 같이 하면 됩니다
Cloudflare 계정 접근C·D·I·J — 새 홈페이지가 올라가 있는 그 계정입니다
옛 사이트 관리자E — 예약 접수를 닫는 데 필요합니다

언제 하면 좋은가 — 손님이 적은 시간(평일 오전)에 시작하는 게 좋습니다. G단계 이후 몇 시간은 옛/새 사이트가 섞여 보이므로, 예약이 몰리는 주말·저녁은 피하세요. 전체는 하루면 되지만, 메일 확인까지 포함하면 이틀 정도 여유를 두는 게 안전합니다.

먼저 끝내면 좋은 것 하나 — 문자 발신번호 지금 카톡 안 되는 손님에게는 안내가 못 나갑니다. 발신번호 심사가 끝나면 그게 자동으로 메워집니다. 도메인 이전과 문자 문제를 동시에 안고 가면, 문제가 생겼을 때 무엇 때문인지 가리기 어렵습니다. 발신번호부터 해결하고 도메인을 옮기는 순서를 권합니다.
