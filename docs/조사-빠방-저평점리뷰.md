- 조사일: 2026-08-21
- 목적: `fantastrick.co.kr/business` 창업 컨설팅 페이지의 "저평점 리뷰 원인 분포" 차트 근거 확보
- 핵심 관심사: **"장치(기계장치) 오류/고장"이 불만 원인 중 몇 위인가**
- 원칙: 실제로 세어본 결과만 기재. 추정·해석은 별도 표기.

## 4. 정량 보강 — 5축 세부평점 (저평점 44건 vs 전체 428건)

한줄평의 50%가 원인 불명이라 정성 코딩만으로는 부족하다. 같은 DB의 **5축 세부평점**으로 정량 검증했다.
(척도 0~7 · 높을수록 좋음 · 전체 평균은 각 축 값 분포를 `group by`로 전수 추출해 직접 가중평균 계산)

| 축 (DB 정의) | 저평점 44건 평균 | 전체 평균 | **격차** | 격차 순위 |
|---|---:|---:|---:|:--:|
| 창의성 | 1.73 (n=44) | 3.95 (n=427) | **−2.23** | 1 |
| **연출** (직원 도움·**장치**·BGM) | 1.75 (n=36) | 3.95 (n=325) | **−2.20** | 2 |
| 문제(퍼즐) | 1.59 (n=44) | 3.43 (n=427) | −1.84 | 3 |
| 스토리/개연성 | 1.48 (n=42) | 3.32 (n=412) | −1.84 | 3 |
| 인테리어 | 1.98 (n=44) | 3.81 (n=426) | −1.83 | 5 |

계산식 예 (문제 축 전체 평균): `(0×5 + 1×18 + 2×54 + 3×139 + 4×148 + 4.5×1 + 5×48 + 6×14) ÷ 427 = 1463.5 ÷ 427 = 3.43`

**"최저 점수를 받은 축" 카운트** (동점은 중복 카운트, 44개 테마 → 총 98회)

| 축 | 최저축이 된 횟수 |
|---|---:|
| 문제(퍼즐) | 25 |
| 스토리/개연성 | 24 |
| 창의성 | 22 |
| 인테리어 | 14 |
| 연출(직원·장치·BGM) | 13 |

### 이 표를 장치 근거로 쓰면 안 되는 이유

`연출` 축의 격차가 2위(−2.20)라고 해서 "장치가 저평점 원인 2위"라고 말할 수 없다. 이유:

1. DB의 `연출` 정의는 **"직원의 도움, 장치, BGM 등을 사용하여 얼마나 큰 임팩트와 인상을 주는지"** — 즉 **장치의 연출력**이지 **장치의 고장 여부**가 아니다.
2. 세 요소(직원·장치·BGM)가 한 축에 묶여 있어 장치만 분리 불가.
3. `연출` 축은 전체 428건 중 **102건이 "-"(해당 없음)** 이다. 자물쇠 중심 테마엔 장치 자체가 없다는 뜻이며, 모수가 다르다.
4. 격차만 보면 1위는 **창의성**(−2.23)이다. "장치가 1위"가 되려면 순위를 임의로 바꿔야 한다.

## 6. 판정 및 차트 설계 권고

### 6-1. "장치 오류"에 대한 솔직한 판정

| 질문 | 답 |
|---|---|
| 저평점 리뷰 44건 중 장치 오류 언급은? | **0건 (0.0%)** |
| 순위는? | **공동 최하위 — 데이터상 존재하지 않음** |
| 데이터가 "장치 오류가 큰 원인"을 뒷받침하나? | **아니오.** |
| 그럼 장치 오류는 문제가 아닌가? | **그것도 아니다.** 커뮤니티에서 반복 등장하는 실재 이슈이며, 조회 1,339회 글까지 있다. 다만 **평점을 깎는 원인이 아니라 환불·분쟁을 만드는 운영 사고**로 나타난다. |

**왜 이런 결과가 나오는가 (해석 — 추정)**
방탈출 리뷰는 대개 **테마 설계 품질**(문제·스토리·인테리어)을 평가한다. 장치 고장은 *그날 그 팀에게만* 일어난 사고여서 테마 평점에 남기보다 **환불 요구·컴플레인**으로 흘러간다. 즉 두 지표가 서로 다른 통로로 빠져나간다. 이건 데이터의 한계가 아니라 **현상 자체의 구조**일 가능성이 높다.

### 6-2. 차트에 쓰면 안 되는 것

- ❌ "장치 오류 XX%" 막대 → **근거 0건. 넣으면 데이터 조작이다.**
- ❌ §4의 `연출` 축 격차(−2.20)를 "장치 오류"로 라벨링 → 정의가 다르다(임팩트 vs 고장). 오독 유도.
- ❌ §5-1 키워드 건수를 비율 파이차트로 → 20건 상한 절단값이라 비율이 성립하지 않는다.

### 6-3. 권장 차트 2종

**차트 A — "저평점 테마의 항목별 평점 (전체 평균 대비)"** ← 메인 차트로 추천
§4 표를 그대로 쓴다. n=44 / 전체 n=428, 출처 명시 가능, 검증된 수치.
메시지: *"저평점 테마는 특정 한 축이 아니라 5개 축이 동시에 무너진다(격차 −1.8 ~ −2.2). 한 곳만 잘해서는 평점이 안 나온다."*

**차트 B — "저평점 리뷰에서 실제로 지적된 원인"** ← 보조
§3-2 표. **"원인 불명 50%"를 지우지 말고 그대로 표시할 것.** 오히려 신뢰도를 올린다.
메시지: *"명시된 원인 1위는 퍼즐과 인테리어 노후(각 25%)."*

**장치 오류는 차트가 아니라 별도 박스로.**
> 「장치 고장은 평점에 안 남는다. 대신 **환불 요구**로 온다.」
> §5-2의 실제 인용 2~3건 + "고장 자체보다 고장 후 대응이 분쟁을 키운다"는 포인트.
> 컨설팅 세일즈 관점에서는 이 프레이밍이 오히려 강하다 — "장치 유지보수 = 평점 방어"가 아니라 **"장치 유지보수 + 사고 대응 매뉴얼 = 환불·분쟁 리스크 관리"** 로 팔린다. 이건 데이터에도 맞고, 실제로 사장님이 돈으로 체감하는 지점이다.

## 7. 수집 방법 및 한계 (반드시 함께 읽을 것)

### 방법
1. 빠방 웹/API/색인 접근성 5종 시도 → 전부 실패 확인(§1).
2. 빠방 앱스토어 리뷰 확보 → 테마 리뷰 아님을 확인하고 데이터에서 제외(§1).
3. 대체 소스로 "방탈출을 하고싶어요" 공개 DB(428테마) 채택. Google Sheets `gviz/tq` 쿼리로 **원본 CSV 직접 추출**(요약 모델 미경유).
4. 등급 C+ 이하 44건 전수 추출 → 한줄평 정성 코딩 + 5축 점수 정량 분석.
5. 44건 전부 `종합 = 5축 평균` 재계산으로 데이터 무결성 검증(44/44 일치).
6. 운영 이슈 보정용으로 디시 방탈출 마이너 갤러리 키워드 스캔 + 개별 글 원문 확보.

### 한계 (차트 각주로 넣을 것)
1. **빠방 데이터가 아니다.** 빠방 리뷰는 접근 불가라 대체 소스를 썼다. 페이지에 "빠방 리뷰 분석"이라고 쓰면 **거짓말이 된다.** 출처를 정확히 표기해야 한다.
2. **평가자 1인(팀) 데이터.** 데이터셋 A는 크라우드 리뷰가 아니라 단일 리뷰어의 큐레이션이다. 개인 취향 편향이 있고, 시트 스스로도 *"추천도의 세부 점수는 다른 요소들에 비해서 훨씬 주관적입니다"* 라고 명시하고 있다.
3. **한줄평이 짧다.** 1~2줄 촌평이라 50%가 원인 불명이다. 원인 식별 표본은 실질 **20건**뿐 — 소표본이다. 25% 같은 수치는 ±큰 오차를 안는다.
4. **커버리지 편향.** 428테마는 전국 방탈출 테마 전체(수천 개 추정)의 일부이며, 수도권·유명 매장 편중이다. 폐업 매장이 다수 포함되어 시점이 섞여 있다.
5. **디시 키워드 카운트는 비율 근거가 아니다.** 1페이지 20건 상한 절단 + 키워드가 긍정 문맥에도 등장. 정성 인용 용도로만 썼다.
6. **장치 오류 0건은 "없다"가 아니라 "이 데이터셋이 못 본다"일 수 있다.** 테마 완성도 평가는 설계상 운영 사고를 포착하지 못한다. §5가 그 반례다.

### 더 정확히 하려면 (후속 제안)
- **1차 데이터 수집**: 판타스트릭 자체 예약자에게 플레이 후 설문(원인 객관식 8개 + 자유 서술) → 자사 데이터로 차트를 만들면 출처 문제·표본 문제가 모두 해결되고, 컨설팅 페이지의 신뢰도가 오히려 올라간다. 표본 100건이면 충분.
- 네이버 지도/카카오맵 방탈출 매장 리뷰는 별점+텍스트가 있어 이상적이지만 SPA·크롤링 차단으로 이번엔 취득 실패. 브라우저 자동화(Playwright)를 쓰면 가능.
