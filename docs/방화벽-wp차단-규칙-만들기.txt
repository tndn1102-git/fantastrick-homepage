클라우드플레어 방화벽에 "옛 워드프레스 주소 차단" 규칙 만들기 (약 1분)
=====================================================================

왜 하나요?
  밖에서 /wp-admin/admin-ajax.php 를 23초마다 두드립니다. 하루 약 4,200번.
  우리 홈페이지에는 없는 주소라 전부 "없는 페이지(404)" 로 돌아가고 있습니다.

  지금도 막고는 있지만, 그건 "서버가 깨어난 뒤에" 막는 거라
  하루 요청 한도(10만 건)는 그대로 까먹습니다.
  방화벽에서 막으면 서버가 아예 안 깨어나서 요청 수에도 안 잡힙니다.

  ※ 예약칸을 긁어가는 수집기(저쪽 회사)는 이 규칙과 아무 상관 없습니다.
    지금처럼 전부 그대로 받아갑니다.

  ※ 제가 코드로 걸어보려 했는데, 클라우드플레어가 옛 방화벽 API 를
    "수정 잠금(maintenance mode)" 으로 막아놨습니다. 새 API 는 권한이 또 달라서
    대시보드에서 직접 만드는 게 제일 빠릅니다. (한 번만 하면 끝입니다)


순서
-----
1) 열려 있는 페이지에서 파란 버튼 [Create rule] (규칙 만들기) 클릭

2) Rule name (규칙 이름) 칸에 아래를 넣습니다.

   old wordpress probe block

3) 조건 칸 오른쪽 위의 [Edit expression] (표현식 편집) 을 클릭합니다.
   -> 칸이 하나짜리 큰 입력창으로 바뀝니다.
   그 안에 아래 한 줄을 통째로 붙여넣기 하세요.
   (아래 "붙여넣을 내용" 을 마우스로 긁어서 복사)


   ────────────── 붙여넣을 내용 (여기부터) ──────────────

(starts_with(http.request.uri.path, "/wp-admin") or starts_with(http.request.uri.path, "/wp-login") or starts_with(http.request.uri.path, "/wp-content") or starts_with(http.request.uri.path, "/wp-includes") or starts_with(http.request.uri.path, "/wp-json") or starts_with(http.request.uri.path, "/wordpress") or http.request.uri.path eq "/xmlrpc.php")

   ────────────── 붙여넣을 내용 (여기까지) ──────────────


4) 아래 "Choose action" (동작 선택) 에서  Block  을 고릅니다.

5) 맨 아래 [Deploy] 버튼 클릭.


6) 저에게 "규칙 만들었어" 라고 알려주세요.
   -> 실제로 막히는지 바로 확인하고, 요청이 정말 줄었는지 숫자로 보고합니다.


참고
-----
- 이 주소들은 우리 홈페이지에 하나도 없습니다(코드로 확인함).
  막아도 손님이 보는 화면은 아무것도 안 사라집니다.
- 아까 열어주신 토큰 권한 두 줄은 헛수고가 아닙니다.
  Analytics 읽기 덕분에 "어느 주소가 요청을 많이 먹나" 조회가 이제 됩니다.
  (실제로 방금 확인: /wp-admin 이 2시간에 1,140건)
