중복 예약 잠금장치가 지금도 살아 있는지 확인하기  (30초)
==========================================================

무엇을 확인하나요?
  같은 테마·같은 날짜·같은 시간에 예약이 두 건 들어가지 못하게 막는
  DB 잠금장치(uq_res_slot)가 지금 데이터베이스에 붙어 있는지 봅니다.

  * 2026-08-07 운영 기록에는 이 잠금장치가 실제로 예약을 막은 흔적이 남아 있습니다.
    그 뒤로 지운 적은 없을 테니 거의 확실하지만, 눈으로 한 번 확인해 두는 겁니다.

  * 아래 명령은 **읽기만 합니다.** 자료를 바꾸거나 지우지 않습니다.


순서
-----
1) 열려 있는 Supabase SQL 편집기 화면에 아래 한 줄을 붙여넣습니다.

2) 오른쪽 아래 [Run] (또는 Ctrl+Enter) 을 누릅니다.


   ────────────── 붙여넣을 내용 (여기부터) ──────────────

select indexname, indexdef from pg_indexes where tablename = 'reservations';

   ────────────── 붙여넣을 내용 (여기까지) ──────────────


3) 결과에서 indexname 이 uq_res_slot 인 줄을 찾습니다.


이렇게 나오면 정상입니다
--------------------------
  indexname    : uq_res_slot
  indexdef     : CREATE UNIQUE INDEX uq_res_slot ON public.reservations
                 USING btree (store_id, theme_id, date, "time")
                 WHERE (status <> 'cancelled'::text)

  확인 포인트 3가지
    · UNIQUE 라는 낱말이 있어야 합니다        (하나만 허용한다는 뜻)
    · (store_id, theme_id, date, "time")      (매장·테마·날짜·시간 조합)
    · WHERE (status <> 'cancelled')           (취소한 건은 칸을 안 차지)


uq_res_slot 이 아예 안 보이면
------------------------------
  잠금장치가 없는 상태입니다. 저에게 알려주세요 —
  다시 걸어야 하고, 그 전에 이미 들어간 중복 예약이 있는지부터 확인해야 합니다.


결과를 저에게 알려주실 때
--------------------------
  "uq_res_slot 있음" 또는 "없음" 한마디면 됩니다.
  화면을 캡처해서 보내주셔도 됩니다.
